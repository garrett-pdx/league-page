# CLAUDE.md — the league site engine

A website for one Sleeper fantasy football league: live standings, matchups, rosters and free
agents, plus a full history archive built offline from Sleeper — every season with its bracket
and final table, records, Stat Lab, a Trophy Room, rivalries, drafts and keepers, manager pages,
a constitution, generated lore and an AI-written weekly blog. SvelteKit, deployed on Vercel.

It began as a fork of [nmelhado/league-page](https://github.com/nmelhado/league-page) (MIT) and
is now a hard fork with its own structure, published as
[Fantasy Football Website with History](https://github.com/garrett-pdx/fantasy-football-website-with-history).

## Start here

**Everything about one league lives in `league/`** (see `league/README.md`). Everything else is
the engine, which holds nothing about any particular league. A league's content changes touch
`league/` only; when a league needs something the engine can't express, add a config option to
the engine — never special-case a league inside a component.

| Job | Use |
| --- | --- |
| Build a site for a league, or re-point this one | the `league-setup` skill |
| Any league numbers: refresh, facts, history, "is that a record" | the `league-data` skill |
| The Monday recap / the midweek preview | `league-recap` / `league-preview` |
| After the title game; before a new season | `league-season` |
| This league's facts, decisions and quirks | `league/NOTES.md` |
| Every config field | `schema/league.schema.json` |

```
league/                    ONE LEAGUE, hand-authored
  league.json              config (validated by schema/league.schema.json)
  home.md, constitution.md, voice.md, NOTES.md, archive-facts.json
  managers/ (photos), brand/ (optional hand-made art), posts/, drafts/
static/data/               GENERATED by the pipeline from Sleeper. Never hand-edit.
static/brand/, favicons, src/theme/_league.scss
                           GENERATED by `npm run brand` from league.json. Never hand-edit.
everything else            the engine
```

## Commands

```
npm install
npm run dev                    # dev server (5173)
npm run dev:league -- <dir>    # serve another league's directory beside it (5174); see below
npm run build                  # production build (Vercel adapter)
DOCKER_BUILD=true npx vite build   # build with the node adapter: works on any Node version
npm run brand                  # colour tokens, brand art and icons from league.json
npm run smui-theme-light       # rebuild static/smui.css (dev never recompiles Sass)
python3 scripts/pull-league-history.py && npm run derive-site-data && npm run derive-narratives
scripts/try-league.sh <id>     # the whole pipeline against any league, in a scratch directory
python3 scripts/league-summary.py [id]       # a league's format, from Sleeper
python3 scripts/sync-managers.py [--photos]  # add every past and present manager to league.json
python3 scripts/suggest-rivals.py [--write]  # rivals from head-to-head history
python3 scripts/find-current-league.py [--write]  # follow Sleeper's renewal to the new season's ID
```

Gotchas, all verified:

- **`npm run build` fails on Node > 22.** Compilation succeeds; the Vercel adapter then refuses
  the Node version. Vercel's builders are unaffected. Use the `DOCKER_BUILD=true` form locally.
- **`npm run lint` is broken twice over**: Prettier flags dozens of files, and ESLint 9 rejects
  `--ignore-path`. Use `npx prettier --check <file>` for what you wrote.
- **`npm run build-docker` / `docker-run`**: the script passes `--verbose`, which this Vite
  rejects. Drop the flag if you need the container path.
- `npm run prepare` compiles the Material theme into `static/smui.css` / `smui-dark.css`; both
  are gitignored. Node >= 20; Python 3.7+, stdlib only, for the pipeline.

**Previewing another league.** `scripts/try-league.sh <id> [dir]` writes a minimal
`league.json` and the whole dataset for any Sleeper league into `try-league/<id>/` (gitignored).
`npm run dev:league -- try-league/<id>` serves the site for it on port 5174, beside the normal
dev server: `LEAGUE_DIR` repoints the `$league` alias, `LEAGUE_DATA` serves `/data/`, and the
preview gets its own Vite cache (two servers sharing one load the Svelte runtime twice). The
generated brand (`static/brand/`, `_league.scss`) is not per-preview. The Python scripts take
`LEAGUE_CONFIG`, `LEAGUE_DATA` and `LEAGUE_DOCS` the same way.

## Architecture

SvelteKit 2 + Svelte 5, with components written in **Svelte 4 idiom** (`export let`, `<slot />`,
stores) and a few Svelte 5 event attributes mixed in. Match the file you're editing; don't
migrate components to runes wholesale.

```
src/
  routes/           # file-based routes; each page dir is +page.js + +page.svelte (src/routes/CLAUDE.md)
    +page.svelte    #   the home page
    seasons/        #   /seasons and /seasons/[year], pre-Sleeper seasons included
    stat-lab/       #   filter / sort / chart over games.json
    manifest.json/  #   the PWA manifest, prerendered from league.json
    api/            #   server endpoints: players, free agents, news, blog
  lib/
    components.js   # barrel for shared components
    stores.js       # svelte stores used as the in-memory cache of Sleeper data
    utils/          # config loader + data layer (src/lib/utils/CLAUDE.md)
      leagueInfo.js #   league.json and league/*.md, as the exports the components use
      helper.js     #   barrel re-exporting helperFunctions/ + leagueInfo
      markdown.js   #   marked, for home.md, the constitution and markdown posts
      blogMarkdown.js   # the markdown blog backend
      tabs.js, pageTitle.js, managerLink.js
    Design/         # primitives with their own barrel (see "The design system")
    History/, Seasons/, StatLab/, Home/, Resources/, <Feature>/
  theme/            # Material (SMUI) theme: _tokens.scss, _site.scss, generated _league.scss
scripts/            # the data pipeline and tools (Python stdlib, plus a few Node scripts)
schema/             # league.schema.json
```

Data flow: a route's `+page.js` `load()` calls helper functions, which fetch Sleeper and memoize
into `src/lib/stores.js`, and returns **unawaited promises**; the `.svelte` file resolves them
with `{#await}` blocks so the shell renders immediately. Keep that shape — `await`ing in `load()`
blocks the whole page on the slowest call.

**Live pages** (matchups, standings, rosters, transactions, free agents, power rankings) read
Sleeper directly. **History pages** (seasons, Stat Lab, schedule luck, head-to-head, Trophy Room,
career bands) read the committed dataset in `static/data/`, built offline by the pipeline.

## The data pipeline

```
python3 scripts/pull-league-history.py   # Sleeper -> league-history, weeks, transactions,
                                         #   ownership, keepers, players (static/data/)
npm run derive-site-data                 # -> games.json, season-notes.json (what pages fetch)
npm run derive-narratives                # -> narratives.json, docs/league-lore.md
```

Walks `previous_league_id` back from `sleeperLeagueId`, so it needs no season list. The opt-in
`refresh-data` GitHub Action runs all three twice a week and commits the result; the
`league-data` skill does the same by hand. Shapes are in `docs/data.md`.

- **One definition of everything.** `derive-narratives.py` imports `derive-site-data.py` as a
  module, `week-facts.py` imports `derive-narratives.py`, and all of them use `scripts/lineup.py`
  for slots and the optimal lineup and `scripts/league_config.py` for the config. Completed
  weeks, official scores, bracket kinds, median results and corrections are defined once.
- **Any roster shape.** `lineup.py` knows every Sleeper slot (QB/RB/WR/TE, K, DEF, FLEX,
  SUPER_FLEX, WRRB_FLEX, REC_FLEX, DL/LB/DB, IDP_FLEX). `sleeper_greedy()` reproduces Sleeper's
  `potential_points` (the check that the slot rules are right); `best_assignment()` is the exact
  optimum, solved as an assignment problem, and is what `max_pf` and bench points use.
  Eligibility is Sleeper's `fantasy_positions`, plus any position a season's own lineups prove,
  plus `overrides.eligibility`.
- **Any format.** Median games (`games.json`'s `median` column; Sleeper's records count them,
  head-to-head never does), divisions, ties, playoffs of any size with byes, two-week rounds
  (`leg`), consolation brackets and toilet bowls (`playoff_type`), orphaned rosters (stand-in
  managers `orphan-<season>-<roster>`), pre-Sleeper seasons and imported drafts, and a brand-new
  league with no completed week (empty files, empty states).
- **The pull writes completed weeks only.** Sleeper serves every scheduled week, future ones at
  0.0 and the current one part-scored; a week counts once the NFL calendar has moved past it.
  `nfl_state` is saved in `league-history.json` so everything downstream is reproducible.
- **Self-checks fail the run before anything is written**: records against Sleeper's, every game
  mirrored, every week's best lineup at least what was scored, brackets complete. **Disagreements
  with Sleeper's settled figures** — a record a game off, a season's potential points out by a
  few points, almost always a post-settlement stat correction or a player whose position has
  changed — are warnings that print the `league.json` override that would pin them;
  `pipeline.strict` makes them failures. Stat corrections that pair up across a game (one PF gap
  matching an opponent's PA gap) are recognised and reported, not failed.
- **The commissioner override is kept** (`custom_points`): official scores use it, and that
  row's `max_pf` is null.

Traps the data has sprung, each of which once produced a wrong fact:

- **Every season carries an empty week 18** with `matchup_id: 0`; falsy `matchup_id` means no
  fixture.
- **A scheduled-but-unplayed season looks completely real**: full rosters, real `matchup_id`s,
  every score 0.0. A season counts only once a point has been scored.
- **Keepers occupy draft slots**, so draft steals and busts filter `is_keeper`.
- **Roster IDs move between seasons.** Bracket rows carry roster IDs meaningful only inside their
  season; key everything on `user_id`.
- **A league imported from another platform has two drafts in its first Sleeper season**; the
  non-primary one is the old season's draft (`history.preSleeper[].importedDraftId`). Merging the
  two corrupts every keeper cost.
- **The losers bracket's `w` is the lower scorer in a toilet bowl** (`playoff_type` 0).

**The static-data budget.** Pages fetch five files: `league-history.json`, `games.json`,
`season-notes.json`, `keepers.json`, `players.json`, each through a reader in
`src/lib/utils/helperFunctions/` that memoizes per session, takes SvelteKit's `fetch`, and never
caches a failure. **Nothing else in `static/data/` is fetched at runtime** — not `weeks.json`,
`transactions.json` or `narratives.json`. Anything new that wants one of those needs a derived,
size-budgeted file, as `games.json` is for `weeks.json`.

## The design system

- **One light theme, no toggle.** `src/app.html` loads a single unconditional `/smui.css`. The
  `media="(prefers-color-scheme: light)"` attribute must stay OFF that link, or a dark-OS visitor
  gets no Material CSS at all. `src/theme/dark/` is still compiled by `npm run prepare` and never
  served.
- **Colours are generated.** `npm run brand` turns `theme` in league.json into
  `src/theme/_league.scss`: a contrast-checked primary ramp (`--brand900` … `--brand050`, measured
  against #ebebeb: brand700 ≥ 7:1, brand500 6.1:1, **brand400 3.54:1, so borders, icons and large
  text only**), `--accentBorder`, the trophy colours (`--trophyFill` is a fill with
  `--trophyOnFill` ink on it, never ink on the page; `--trophyInk` is for that) and `--emblem`
  (art only). Interactive text is `--accentInk`. Other tokens (type, widths, radii, elevation)
  are in `_tokens.scss`.
- **Brand art is generated too**: seal, simple seal, wordmark, ribbon and laurel from
  `scripts/brand-templates/` into `static/brand/`, and the raster icons from the simple seal
  (`scripts/render-icons.js`, which insets the maskable Android icons to 72%), plus the iOS launch
  screens from the seal and wordmark, one per size `src/app.html` declares. A file in
  `league/brand/` replaces the generated one. An SVG shown through `<img>` gets no page CSS and no
  webfonts, so colours are literal hex and text widths are pinned with `textLength`; an XML
  comment containing two consecutive hyphens is a parse error that blanks the file.
- **Type**: Oswald for headings, Material buttons and nav tabs, through the
  `--mdc-typography-*-font-family` hooks. Never set the base `--mdc-typography-font-family` or
  `subtitle1`; they reach body text and inputs. Data-table cells use Roboto's tabular figures.
- **The 12px / 44px floor is a standing rule.** Nothing renders below 12px, table data at least
  14px, and every interactive target is at least 44px tall on phones and touch screens (inline
  links in prose excepted). When something doesn't fit, change the layout, never the type size.
- **Global rules live in `src/theme/_site.scss`**, `@use`d by `_tokens.scss`. It cannot override
  a scoped rule (the hash class wins). **`--stickyBar`** (61px below 951px, 0 above) is the
  sticky phone nav's height: anything that scrolls to an in-page target uses
  `scroll-margin-top: var(--stickyBar)`.
- **Primitives in `src/lib/Design/`** (`Card`, `StatTile`, `SectionHeading`, `SegmentedControl`,
  `Countdown`, `PageHeader`, `Disclosure`) with their own barrel. `PageHeader` is the title block
  on every page, mounted in the route file; its intro comes from `pageIntro(key)`, which
  league.json `pages` can override. `Disclosure` mounts its content only when opened.
  `SectionHeading` styles a class, never a tag (it renders through `<svelte:element>`).

## The nav

`src/lib/utils/tabs.js` is the whole structure; read its header comment before editing.

- **Top bar:** Managers, Matchups, Standings, Free Agents, Trades & Waivers, Blog, League ▾. No
  Home tab (the seal links home).
- **League ▾** holds groups: This Season (Rosters), History (Seasons, Trophy Room, Records,
  Rivalry, Drafts, Stat Lab), Rules & Tools (Constitution when `league/constitution.md` exists,
  then league.json `links` with `nav` set, Resources, Go to Sleeper). Off-site entries are
  detected by URL, open in a new tab and carry an ↗ icon.
- **The highlight follows the page** via `findTab` / `currentDest`; the same lookup gives the
  browser tab title (`pageTitle.js`).
- Constraints: exactly one `nest: true` tab; the Blog tab stays top-level with the label `Blog`
  (hidden when the blog is off); Managers is hidden when `managers` is empty.

## The home page

`src/routes/+page.svelte`: two columns above 950px — league name, `league/home.md`, the featured
(or newest) blog post and power rankings on the left; the NFL-week banner, the draft countdown or
season milestone, the reigning champion and recent transactions on the right. **On phones every
block is a flex item of `#home` with a CSS `order`**, interleaving the columns in reading order;
a new home block needs an `order` too. `home.md` is `{@html}`-injected trusted content, styled
from `_site.scss` (`homeLede`, `homeLinks`, `homeRules`).

## Conventions

- Import shared things from the barrels — `$lib/components`, `$lib/utils/helper`, `$lib/Design`.
  League content comes in through `$lib/utils/leagueInfo`; nothing else imports `$league` except
  the optional-file globs (`ArchiveCard`, the blog API route).
- Managers are keyed by Sleeper `user_id` everywhere. Roster IDs are per season.
- Photos are served from `league/managers/`, never hotlinked from Sleeper (an avatar URL changes
  when its owner changes it).
- Secrets: the blog's Contentful tokens (`VITE_CONTENTFUL_SPACE`,
  `VITE_CONTENTFUL_CLIENT_ACCESS_TOKEN`) only when `blog.backend` is "contentful". A Contentful
  *management* token must never be a `VITE_` variable.
- Sleeper's API is public, read-only and unauthenticated; there is no write path and there
  shouldn't be one.

## Upstream bugs fixed here

Worth knowing because a fix from upstream could reintroduce them: `goto()` throws on external
URLs, so nav and footer test the destination (not the label) for off-site links;
`.manager:hover` used a nonexistent `bar()` CSS function; `getTeamNameFromTeamManagers` and
`renderManagerNames` were unguarded for a roster missing from a season; `getLeagueTransactions`
crashed on a failed Sleeper fetch; and the records page divided points by Sleeper's record,
which halves points per game in a median league.

`src/lib/version.js` is the engine version; `/api/checkVersion` compares it with the template's
published `package.json`, and the footer offers an update (`scripts/update-engine.py`) when that
is newer.
